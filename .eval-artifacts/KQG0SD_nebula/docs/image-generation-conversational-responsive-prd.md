# 图片生成对话式响应式体验 PRD

> 状态：待实现  
> 范围：Woohoo 主工作区内的 `图片生成` Tab V2 交互体验  
> 依赖：`docs/image-generation-tab-integration-prd.md` 中的 Tab 集成、公共资产库、全局积分、配置 API 通道约束  
> 核心方向：参数收进创作对话框，避免传统右侧表单工作台的古板感

## 1. 背景

当前图片生成 Tab 已经明确不是独立应用，也不是资产库的替代入口。下一阶段需要把它从“参数面板 + 单张预览”的工具页，升级为更接近创作场景的对话式生成体验：

- 用户主要通过自然语言持续描述、追问、改图和重试。
- 参数不再作为一个独立右栏表单压在页面上，而是进入创作对话框，以 chip、快捷控件和展开面板的方式出现。
- 系统以消息流方式展示生成中、成功、失败和扣费状态。
- 每次生成的图片仍自动沉淀到公共资产库。
- 移动端需要像真正的移动创作工具，而不是桌面表单的缩小版。

即梦类产品给 Woohoo 的参考点不是“另做一个完整智能画布”，而是降低创作门槛：默认让用户先说需求，模型、尺寸、数量等参数跟随输入框出现，用户需要精调时再展开。

## 2. 目标

1. 图片生成 Tab 保持主工作区内的一等 Tab，不新增独立路由、独立 SPA 或独立构建入口。
2. UI 从固定双栏升级为对话式创作流，支持连续生成、重试、变体、复用上次参数。
3. 参数收敛到创作对话框内，桌面和移动端都避免“右侧大表单 + 左侧预览”的工具软件感。
4. 桌面端适合长时间创作，移动端适合单手输入、快速调参和快速查看结果。
5. 生成结果在图片生成 Tab 中只作为当前创作会话的结果卡片展示，用户侧长期历史仍以公共资产库为准。
6. API 配置不暴露底层 `/v1/responses`、`/v1/chat` 或 `/v1/images/generations` 选择，前端只选择 API 通道和模型。

## 3. 非目标

- 不做独立 `/image-studio` 页面。
- 不恢复 `src-image-studio/`、`dist-image-studio/` 或 `vite.image-studio.config.ts`。
- 不在图片生成 Tab 内嵌一套资产库列表。
- 不新增图片生成私有余额、私有积分或私有资产历史。
- 不在设置页做复杂的多模态能力勾选矩阵。
- V2 不做完整无限画布、图层编辑、局部重绘和抠图工具；这些能力可以作为后续“图像编辑/画布”阶段规划。
- 不把参数做成常驻右侧复杂检查器；高级参数只能作为创作对话框的展开层出现。

## 4. 体验原则

### 4.1 对话优先

默认入口是创作对话框，而不是参数表单。用户看到的是一条创作对话流：

- 用户消息：本次 prompt、参考图、使用的关键参数摘要。
- 系统消息：排队、生成中、失败、退款、完成。
- 结果卡片：生成图片、操作按钮、保存到资产库状态。
- 后续输入：默认继承上一轮参数，用户可以在输入框里的 chip 上快速调整。

### 4.2 参数在对话框内渐进暴露

创作对话框由四层组成：

1. 主输入区：prompt textarea，支持多行输入。
2. 附件区：参考图、从资产库带入的图片、未来图生图入口。
3. 参数 chip 行：模型、比例/尺寸、数量、预计积分、更多参数。
4. 操作区：生成、停止/重试、清空草稿。

常用参数直接以内联 chip 呈现：

- `模型`：显示当前模型，点击打开轻量选择浮层。
- `比例`：用 1:1、3:4、4:3 等更自然的选项展示，内部映射到实际 size。
- `数量`：用 stepper 或 segmented control，避免裸数字输入。
- `积分`：只读 chip，随参数变化实时更新预计消耗。
- `更多`：打开对话框内展开面板，承载 API 通道、种子、风格预设、负面词、参考图权重、高清增强等低频参数。

移动端同样遵循这个结构，不把参数拆到一个远离输入框的表单页。

### 4.3 资产库唯一历史

图片生成 Tab 可以展示“当前会话里的结果卡片”，但不能承担长期历史库职责：

- 生成成功后立即写入公共资产库。
- 结果卡片展示 `已保存到资产库` 状态和 `在资产库查看` 操作。
- 刷新页面后，图片生成 Tab 不需要重建完整历史；公共资产库负责长期浏览。

### 4.4 移动端不降级

移动端不是桌面 UI 的压缩版，而是独立布局：

- 单列消息流。
- 底部固定创作对话框。
- 参数 chip 与输入框同层展示，更多参数用底部展开层。
- 图片结果优先完整可见，操作按钮不遮挡图片。
- 适配安全区和软键盘，避免输入框覆盖当前生成状态。

## 5. 信息架构

### 5.1 桌面端布局，大于等于 1200px

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部轻量状态栏：图片生成 / 当前项目 / 全局余额 / 刷新          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                    创作消息流                                │
│        - 空状态 prompt 示例                                  │
│        - 用户 prompt 消息                                    │
│        - 生成中占位                                          │
│        - 结果卡片                                            │
│        - 错误/退款状态                                       │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│ 创作对话框                                                   │
│ [参考图] [模型 chip] [比例 chip] [数量 chip] [积分 chip] [更多] │
│ [prompt textarea.........................................]    │
│                                      [重新生成] [生成]         │
└──────────────────────────────────────────────────────────────┘
```

桌面端不默认显示常驻右侧参数栏。页面重点是消息流和底部创作对话框。更多参数从对话框内展开为浮层或内嵌抽屉，展开后覆盖在 composer 上方，不把页面切回表单工作台。

### 5.2 宽屏增强，大于等于 1440px

宽屏可以利用额外空间，但不能回到古板右栏：

- 消息流最大宽度保持可读，不拉满全屏。
- 结果卡片可以使用更大的图片预览和横向多图网格。
- 创作对话框居中，宽度随消息流对齐。
- 可选展示“当前参数摘要”小浮条，但只读，不作为主编辑入口。

### 5.3 平板端，768px 到 1199px

```text
┌──────────────────────────────────────────────┐
│ 顶部轻量状态栏：图片生成 / 余额               │
├──────────────────────────────────────────────┤
│ 创作消息流                                    │
├──────────────────────────────────────────────┤
│ 创作对话框                                    │
│ [模型] [比例] [数量] [更多]                    │
│ [prompt textarea.........................]    │
│                                  [生成]       │
└──────────────────────────────────────────────┘
```

平板端参数仍在对话框里。`更多` 打开底部 Sheet，Sheet 内容来自同一套参数配置，不另做右栏。

### 5.4 手机端，小于 768px

```text
┌──────────────────────────┐
│ 图片生成            余额 │
├──────────────────────────┤
│ 消息流                    │
│ - 生成中骨架图             │
│ - 结果图片卡片             │
│ - 操作栏                   │
├──────────────────────────┤
│ 固定底部创作对话框          │
│ [参考图缩略图]              │
│ [prompt textarea]          │
│ [1:1] [1张] [模型] [更多]   │
│                   [生成]    │
└──────────────────────────┘
```

手机端对话框有两种状态：

- 收起态：一行 prompt 输入 + 参数 chip + 生成按钮，适合快速补一句。
- 展开态：textarea 增高，参考图托盘展开，更多参数以 Sheet 从对话框上方弹出。

手机端输入器高度必须可控，收起态不超过视口高度的 28%，展开态不超过 48%。textarea 聚焦时，消息流自动保留底部 padding，不能让当前结果被键盘和输入器遮住。

## 6. 核心用户流程

### 6.1 文生图

1. 用户进入图片生成 Tab。
2. 在创作对话框输入自然语言 prompt。
3. 在输入框下方 chip 快速调整比例、数量、模型。
4. 点击生成。
5. 消息流新增用户消息和生成中卡片，用户消息里保留参数摘要。
6. 后端通过已配置 API 通道调用图片生成能力。
7. 成功后扣费完成，图片写入公共资产库。
8. 结果卡片显示图片和操作。

### 6.2 继续修改

结果卡片提供：

- `再次生成`：使用同一 prompt 和参数重新生成。
- `变体`：把当前图片作为参考图，带入下一轮 prompt。
- `作为参考`：只附加图片到创作对话框，不立即生成。
- `下载`：下载当前资产文件。
- `在资产库查看`：切换到公共资产库并定位该资产。

V2 可以先实现 `再次生成`、`下载`、`在资产库查看`。`变体` 和 `作为参考` 需要后端支持图生图或多模态输入后再启用。

### 6.3 参数继承与修改

- 下一轮默认继承上一轮的模型、比例、数量和 API 通道。
- 用户修改 chip 后，只影响下一次生成，不回写历史消息。
- 历史消息展示当时使用的参数摘要，避免用户混淆。
- `再次生成` 使用对应结果卡片自己的参数，而不是当前 composer 参数。

### 6.4 失败处理

失败不应只弹 toast。消息流中保留失败卡片：

- 展示失败原因。
- 显示积分是否退回。
- 提供 `重试`。
- 如果是 API 通道问题，引导去设置页，但不暴露底层接口路径。

## 7. 组件规划

### 7.1 `ImageGenerationPanel`

容器组件，负责：

- 读取当前项目、资产、积分、API 通道。
- 管理当前对话会话。
- 处理生成请求、刷新资产库、刷新积分。
- 根据断点选择桌面、平板、手机布局。

### 7.2 `ImageGenerationThread`

消息流组件，负责：

- 渲染用户 prompt 消息。
- 渲染参数摘要 chip。
- 渲染生成中占位。
- 渲染结果卡片。
- 渲染失败状态。
- 自动滚动到最新消息，但用户向上查看旧消息时不强制抢滚动。

### 7.3 `PromptComposer`

创作对话框组件，负责：

- prompt textarea。
- 参考图入口。
- 参数 chip 行。
- 生成按钮和快捷键。
- 移动端安全区、键盘适配。
- 展开和收起状态。

桌面端支持 `Ctrl/Command + Enter` 生成；移动端不展示快捷键说明。

### 7.4 `ComposerParameterChips`

对话框内参数快捷控件，负责：

- 模型 chip。
- 比例/尺寸 chip。
- 数量 stepper。
- 预计积分 chip。
- 更多参数入口。

这些控件必须视觉上属于创作对话框，而不是独立工具栏。

### 7.5 `ComposerParameterSheet`

更多参数展开层，负责：

- 桌面端：从创作对话框上方弹出为轻量面板。
- 平板和手机端：从底部对话框上方展开为 Sheet。
- 关闭后保留参数状态。
- 打开时不触发整页横向滚动。
- 高度不超过视口 82%，手机端优先展示模型、API 通道、尺寸、数量。

### 7.6 `GenerationResultCard`

结果卡片，负责：

- 图片预览。
- 资产保存状态。
- 下载。
- 再次生成。
- 在资产库查看。
- 未来扩展变体、参考图、高清增强。

结果卡片不能展示一组历史资产列表，只展示当前会话中由用户刚生成的结果。

## 8. 状态模型

前端新增会话级状态，不替代后端审计表和公共资产库：

```ts
type ImageGenerationTurnStatus =
  | 'draft'
  | 'queued'
  | 'generating'
  | 'completed'
  | 'failed';

type ImageGenerationTurn = {
  id: string;
  prompt: string;
  params: {
    endpointId: string;
    model: string;
    size: '1024x1024' | '1024x1536' | '1536x1024';
    count: number;
  };
  status: ImageGenerationTurnStatus;
  generationId?: string;
  assetIds: string[];
  error?: string;
  creditsCost?: number;
  creditsRefunded?: boolean;
  createdAt: number;
  completedAt?: number;
};

type ImageGenerationComposerState = {
  prompt: string;
  referenceAssetIds: string[];
  params: ImageGenerationTurn['params'];
  expanded: boolean;
  parameterSheetOpen: boolean;
};
```

V2 默认只在前端内存中保留当前会话。后续如果要持久化“创作会话”，也只能保存会话元数据和资产引用，不能绕过公共资产库另建图片历史。

## 9. API 与后端约束

前端生成请求仍使用当前内部接口：

```http
POST /api/image-gen/generations
```

请求体保持产品语义：

```json
{
  "projectId": "string",
  "endpointId": "string",
  "prompt": "string",
  "model": "gpt-image-1",
  "size": "1024x1024",
  "n": 1
}
```

约束：

- 前端不发送 `apiMode`。
- 前端不发送底层路径选择。
- 后端内部按已配置 API 通道处理 `/v1/responses`、`/v1/chat` 或兼容返回格式。
- Responses 和 Chat 聚合返回的 base64 图片必须落盘为资产文件，再写入公共 `assets` 表。
- 如果失败发生在扣费后，必须走全局积分退款流程。

## 10. 视觉与交互规范

- 整体保持 Woohoo 工作台风格，不做营销页、独立创作社区或模板广场。
- 创作对话框是页面视觉中心，应该像现代 AI 输入器，而不是传统表单。
- 参数 chip 要轻、短、可扫读，避免长标签和多行挤压。
- 卡片圆角不超过 8px。
- 按钮优先使用 `lucide-react` 图标。
- 结果图片需要稳定宽高，加载、失败、hover 操作不能导致布局跳动。
- 文案使用正常 UTF-8 中文，禁止乱码。
- 不使用大面积单一紫蓝渐变作为主视觉。
- 空状态可以提供 2 到 4 个 prompt 示例，但不能变成教程页。
- 积分、保存状态、失败原因必须在当前上下文可见，不能只依赖 toast。

## 11. 响应式验收标准

### 桌面端

- 1440px 宽度下，消息流和创作对话框居中且对齐。
- 页面不出现常驻右侧参数表单。
- 常用参数能在创作对话框内直接完成。
- 更多参数展开后不打断消息流阅读。
- 生成中占位有明确内容，不出现空白区域。
- 结果图片不会被底部创作对话框遮挡。

### 平板端

- 1024px 宽度下，不出现横向滚动。
- 常用参数能在创作对话框 chip 行完成。
- 参数 Sheet 打开和关闭后布局稳定。
- composer 展开时不会把消息流压到不可用。

### 手机端

- 390px 宽度下，不出现横向滚动。
- 软键盘弹出时仍能看到输入框和生成按钮。
- 参数 chip 在手机端可点击、可滑动或自动换行，但不能撑出屏幕。
- 更多参数 Sheet 从底部 composer 上方展开，关闭后回到输入。
- 结果卡片操作按钮可点击，文字不溢出。
- 创作对话框不会永久遮住最后一张生成结果。
- 图片预览保持完整，不被强制裁切成不可识别状态。

## 12. 功能验收标准

- 主工作区 Tab 中能进入 `图片生成`。
- prompt、模型、比例、数量、预计积分都能在创作对话框中完成查看或编辑。
- 生成成功后，消息流展示结果卡片。
- 用户消息展示当次参数摘要。
- 生成成功后，公共资产库能看到对应图片资产。
- 结果卡片支持下载。
- 结果卡片支持再次生成。
- 结果卡片支持跳转或定位到公共资产库。
- 图片生成 Tab 不展示公共资产库列表的复制版本。
- 图片生成 Tab 不维护私有余额。
- 无可用 API 通道时，创作对话框展示可恢复状态，不崩溃。
- 生成失败时，消息流保留失败卡片并支持重试。
- `npm run typecheck` 通过。
- `npm run build` 通过。
- `cargo check --manifest-path server/Cargo.toml` 通过。

## 13. 分期建议

### Phase 1：对话框参数化骨架

- 拆分 `ImageGenerationPanel`、`ImageGenerationThread`、`PromptComposer`、`GenerationResultCard`。
- 新增 `ComposerParameterChips`，把模型、比例、数量、积分放入 composer。
- 移除常驻右侧参数检查器设计。
- 用当前内存状态实现消息流。
- 生成中占位和失败卡片落地。

### Phase 2：响应式 composer

- 桌面居中 composer。
- 平板 composer 紧凑布局。
- 手机底部固定 composer。
- 手机端展开态、键盘安全区和消息流 padding。
- `ComposerParameterSheet` 完成桌面浮层和平板/手机 Sheet。

### Phase 3：结果操作闭环

- 再次生成。
- 下载。
- 在资产库查看。
- 生成后刷新公共资产库和全局积分。
- 历史消息参数摘要。

### Phase 4：参考图和变体

- 将公共资产库图片作为参考图带入下一轮。
- 结果卡片 `作为参考`。
- 后端支持图生图或 Responses 多模态输入后再开放 `变体`。

### Phase 5：轻量智能辅助

- prompt 示例。
- 最近参数复用。
- 自动生成 prompt 摘要。
- 根据错误类型给出可执行恢复动作。

## 14. 待确认问题

1. `在资产库查看` 是切换到资产库 Tab 并定位资产，还是打开资产详情弹窗？
2. 当前会话是否需要在刷新页面后恢复最近一次生成记录？
3. 是否要在 V2 就支持参考图上传，还是等后端多模态输入稳定后再上？
4. 模型列表是否继续允许用户手输，还是只展示 API 通道返回的默认模型和推荐模型？
5. 参数 chip 的默认展示顺序是否固定为 `比例 / 数量 / 模型 / 积分 / 更多`？
